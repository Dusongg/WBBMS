# 二、点击“重建榜单”后，系统依次做了什么

## 1) 前端（`web/src/views/RankingList.vue`）

1. 用户点击“重建当前榜单”按钮，触发 `handleRebuild()`。
2. 前端弹出确认框（`ElMessageBox.confirm`）。
3. 用户确认后，调用 `rebuildRanking(currentType, currentPeriod)`（`web/src/api/ranking.js`）。
4. 发起请求：`POST /api/ranking/rebuild`。
5. 请求成功后，提示“重建成功”，随后调用 `fetchRanking()` 重新拉取榜单数据并刷新页面。

> 说明：当前后端接口 `POST /rebuild` 实际是重建所有榜单，不只当前 tab。

## 2) 路由与鉴权（`router/ranking.go` + `middleware/jwt.go`）

1. 路由命中 `/api/ranking/rebuild`。
2. `rankingRouter.Use(middleware.JWTAuth())` 先执行：
   - 解析 `Authorization: Bearer <token>`；
   - 将 `user_id`、`username`、`role` 写入 Gin Context。
3. 进入 `api/v1/ranking.go` 的 `RebuildRankings`。

## 3) API 层（`api/v1/ranking.go`）

1. 从 Context 读取 `role` 并做管理员权限校验（支持 `model.UserRole` 和 `string` 两种类型）。
2. 校验通过后调用 `service.RebuildAllRankings(ctx)`。
3. 成功返回：
   - `code: 200`
   - `msg: "重建成功"`
4. 失败返回：
   - `403`（权限不足）或
   - `500`（重建失败）

## 4) Service 层重建（`service/ranking_service.go`）

`RebuildAllRankings()` 会依次重建 4 个榜单：

1. 点赞周榜（`like + week`）
2. 点赞月榜（`like + month`）
3. 收藏周榜（`favorite + week`）
4. 收藏月榜（`favorite + month`）

每次重建调用 `rebuildRanking(type, period, periodKey)`，内部步骤：

1. 计算时间窗口（周/月）；
2. 查询 MySQL 行为表统计：
   - 点赞榜：`book_likes` 按 `created_at` 分组计数；
   - 收藏榜：`book_favorites` 按 `created_at` 分组计数；
3. 生成对应 Redis Key（例如 `rank:likes:week:2026-W10`）；
4. 删除旧榜单 key（`DEL`）；
5. 将统计结果逐条写入 Redis ZSet（`ZIncrBy`）；
6. 设置过期时间（`Expire`）。

## 5) Redis 层发生的事情

1. 旧榜单数据被清空；
2. 新榜单写入 ZSet（`member=book_id`，`score=count`）；
3. 后续榜单查询走 Redis TopN（`ZRevRangeWithScores`）。

> 当前已做兜底：`score <= 0` 的榜单成员会被过滤/移除，避免出现负分展示。

## 6) MySQL 层发生的事情

1. 在“重建榜单”动作中，MySQL主要作为统计数据来源（读）；
2. 重建本身不直接写 MySQL 榜单表；
3. 点赞/取消点赞对 MySQL 的落库由 Stream Worker 异步完成（最终一致）。
