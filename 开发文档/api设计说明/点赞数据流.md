# 当前点赞数据流（实际实现）

在 `ToggleLike`（`service/like_service.go`）里，整体流程如下：

## 1) 先在 Redis 判断当前是否已点赞

- 使用用户点赞集合做状态判断（类似 `user:likes:{userId}`）。
- 根据当前是否已点赞，决定执行“点赞”还是“取消点赞”。

## 2) 立即写 Redis（同步）

点赞/取消点赞会先同步更新 Redis，保证接口快速返回：

1. 用户点赞集合加/减（是否已点赞状态）。
2. 图书统计 `book:stats:{bookId}` 中 `like_count` 加/减。
3. 榜单 ZSet（周榜、月榜）分数加/减。

## 3) 写 Stream 消息（异步）

- 将本次操作写入 `StreamLikeActions`，用于异步落库。
- 这样主链路不阻塞 MySQL，接口延迟更低。

## 4) Worker 消费 Stream，批量落 MySQL

Worker 消费点赞流后，批量写入数据库：

1. 写 `book_likes` 行为表（点赞/取消点赞记录）。
2. 更新 `books.like_count` 统计字段。

## 5) 架构特征

这是典型的 **Redis 优先 + MySQL 最终一致** 架构：

- 前端会先看到 Redis 的最新结果（响应快）。
- MySQL 会通过异步消费在稍后追平（最终一致）。
