# P1：分布式追踪（OpenTelemetry + Jaeger）实施计划

## 1. 目标

- 每个 HTTP 请求生成 `trace_id`，贯穿 API → Redis → MySQL
- 在 Jaeger UI 中查看完整调用链与耗时
- 响应头返回 `X-Trace-ID`，便于前端/日志关联

## 2. 技术选型


| 组件    | 方案                      |
| ----- | ----------------------- |
| SDK   | OpenTelemetry Go        |
| Gin   | otelgin 中间件             |
| GORM  | otelgorm 插件             |
| Redis | otelredis 或手动 Span      |
| 后端    | Jaeger All-in-One（OTLP） |


## 3. 实施步骤

1. 配置：config.yaml 增加 tracing 段，支持 OTEL_EXPORTER_OTLP_ENDPOINT 等环境变量
2. 初始化：observability/tracing.go 创建 TracerProvider，OTLP exporter 指向 Jaeger
3. main.go：api/all 模式启动前初始化 Tracer，退出时 Shutdown
4. Router：接入 otelgin 中间件，设置 X-Trace-ID 响应头
5. GORM：GormMysql 时注册 otelgorm 插件
6. Redis：如有 otelredis 则用，否则在关键调用处手动创建 Span
7. Docker：增加 jaeger 服务，暴露 4317(OTLP gRPC)、16686(UI)
8. 文档：更新架构v2.md，补充验证步骤

## 4. 验证

- 启动栈后访问任意 API
- 打开 [http://localhost:16686，在](http://localhost:16686，在) Jaeger UI 中搜索 trace
- 检查 trace 包含 HTTP、DB、Redis 等 span
